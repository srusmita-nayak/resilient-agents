# Protected Coordination Protocol Specification

## 1. Message Schema Specification

Every communication packet exchanged across the virtual channel conforms to a validated, versioned Pydantic schema:

| Field | Type | Description |
|---|---|---|
| `msg_id` | `str` | Unique message identifier generated by sender; preserved across retransmissions |
| `kind` | `Enum` | Protocol packet type: `DATA`, `ACK`, `SYNC_REQ`, `SYNC_RESP`, `HEARTBEAT` |
| `sender` | `str` | Agent identifier of the transmitting agent |
| `receiver` | `str` | Agent identifier of the intended recipient |
| `task_id` | `str` | Benchmark instance identifier |
| `run_id` | `str` | Experiment execution identifier |
| `round` | `int` | Current round or coordination epoch |
| `payload` | `Dict` | Serialized node state mappings: `node_id -> (color, version)` |
| `corr_id` | `str?` | Correlation ID matching target `msg_id` for `ACK` or `SYNC_RESP` |
| `attempt` | `int` | Retransmission counter (1 for initial transmission) |
| `sent_at` | `float`| Virtual simulation timestamp when message was scheduled |
| `schema_version`| `str` | Protocol schema version (current: `"1.0"`) |

## 3. Core Mechanisms

### 3.1 Unique Identifiers & Idempotent Retransmission
Every data transmission assigns a universally unique `msg_id`. When retransmitting due to unacknowledged delivery, the identical `msg_id` is retained while the `attempt` counter is incremented.

### 3.2 Acknowledgment (ACK) Tracking
Senders maintain an active `pending_acks` table indexed by `msg_id`. When a recipient delivers a `DATA` packet, it immediately returns an `ACK` specifying `corr_id = message.msg_id`. Upon receiving an `ACK`, the sender matches both `corr_id` and expected sender identity before disarming the retry timer. Unmatched or late ACKs are discarded safely.

### 3.3 Bounded Retransmission with Exponential Backoff
If an ACK is not received within `ack_timeout` virtual units:
$$\Delta t_{backoff} = t_{base} \times (\beta)^{attempt - 1}$$
Where $t_{base} = 3.0$ and $\beta = 1.5$. Retransmissions are strictly bounded by `max_retries` (default: 3 or 4).

### 3.4 Duplicate Suppression (At-Most-Once Application)
Recipients maintain a bounded FIFO history of seen `msg_id` entries (capacity: 1000). If a duplicate packet arrives:
1. An `ACK` is immediately re-sent to the sender to terminate its retry timer.
2. The payload is **not** re-applied to the local agent state, ensuring strict at-most-once execution.

### 3.5 Monotonic Versioning & Causal Stale Rejection
Each graph node is owned by a single authoritative agent. The owner increments the node's version counter $v \in \mathbb{N}$ upon color updates:
- When a neighbor receives state update $(color, v_{in})$ for node $u$:
- If $v_{in} \le v_{local}$, the update is flagged as stale, rejected, and logged as `STALE_REJECTED`.
- If $v_{in} > v_{local}$, the update is accepted.
This prevents out-of-order delayed packets from reverting newer constraint decisions.

### 3.6 Authoritative Snapshots & Re-coordination
When round barriers expire due to temporary partitions or dropped messages:
1. The waiting agent dispatches a `SYNC_REQ` to missing peers.
2. The peer responds with a `SYNC_RESP` containing authoritative `(color, version)` tuples for all owned nodes.
3. State is merged using monotonic version comparisons.

### 3.7 Degraded Fallback on Exhaustion
If all retries and re-coordination attempts expire without peer contact:
1. The link is marked `DEGRADED_PEER`.
2. The agent proceeds to make its local constraint decision rather than stalling the simulation in deadlock.
3. When communication resumes in later rounds, newer monotonic versions immediately restore global causal consistency.

## 4. Formal Assumptions & Guarantees

- **Guarantees Provided:**
  - Bounded at-least-once delivery attempts.
  - At-most-once payload application per message ID.
  - Monotonic causal ordering at node boundaries.
  - Deadlock freedom under arbitrary packet drop rates.
- **Assumptions:**
  - Crash-free agents (agents do not experience silent fail-stop or Byzantine corruption).
  - Reliable local memory storage for bounded seen history.
  - No physical network corruption (packet payloads are not bit-flipped).
